# Implementation patterns

Code patterns to follow in 540 News. They worked in the earlier production app this design is based on, and are adapted here: an owner plus invitation-based roles instead of an admin list, and no in-app AI.

## 1. Configuration

All deployment values come from the environment. One zod schema parses them once, in the host entry.

```ts
// server/config.ts
import { z } from "zod";

const envSchema = z.object({
  PUBLIC_BASE_URL: z.url(),
  OWNER_EMAIL: z.email("OWNER_EMAIL must be the owner's Google email"),
  BETTER_AUTH_SECRET: z.string().min(32, "BETTER_AUTH_SECRET must be at least 32 characters"),
  GOOGLE_CLIENT_ID: z.string().min(1),
  GOOGLE_CLIENT_SECRET: z.string().min(1),
  CLIENT_IP_HEADER: z.string().optional(),
  RATE_LIMIT_REQUESTS_PER_MIN: z.coerce.number().int().positive().default(60),
  RATE_LIMIT_WRITES_PER_MIN: z.coerce.number().int().positive().default(10),
  RATE_LIMIT_UPLOADS_PER_MIN: z.coerce.number().int().positive().default(5),
});

export interface AppConfig {
  baseUrl: string;                 // no trailing slash
  ownerEmail: string;              // lower-cased
  authSecret: string;
  google: { clientId: string; clientSecret: string };
  host: "cloudflare" | "node";
  clientIpHeaders: string[];
  rateLimits: { requests: number; writes: number; uploads: number };
}

export function loadConfig(env: Record<string, unknown>, host: AppConfig["host"]): AppConfig {
  const parsed = envSchema.safeParse(env);
  if (!parsed.success) {
    const problems = parsed.error.issues.map((i) => `${i.path.join(".")}: ${i.message}`);
    throw new Error(`Invalid configuration:\n  ${problems.join("\n  ")}`);
  }
  const v = parsed.data;
  return {
    baseUrl: v.PUBLIC_BASE_URL.replace(/\/+$/, ""),
    ownerEmail: v.OWNER_EMAIL.trim().toLowerCase(),
    authSecret: v.BETTER_AUTH_SECRET,
    google: { clientId: v.GOOGLE_CLIENT_ID, clientSecret: v.GOOGLE_CLIENT_SECRET },
    host,
    clientIpHeaders: [v.CLIENT_IP_HEADER ?? (host === "cloudflare" ? "cf-connecting-ip" : "x-forwarded-for")],
    rateLimits: { requests: v.RATE_LIMIT_REQUESTS_PER_MIN, writes: v.RATE_LIMIT_WRITES_PER_MIN, uploads: v.RATE_LIMIT_UPLOADS_PER_MIN },
  };
}
```

`loadConfig` throws one readable error that lists every bad variable.

## 2. Host entry and services

```ts
// hosting/cloudflare/worker.ts
import { createRequestHandler } from "react-router";
import { drizzle } from "drizzle-orm/d1";
import { createRouterContext } from "../../app/context";
import { createServices, handleRequest, type Services } from "../../server/app";
import { fetchClientMetadataViaFetch } from "../../server/auth/cimd-fetch";
import { loadConfig, type AppConfig } from "../../server/config";
import * as schema from "../../server/db/schema";
import { R2MediaStore } from "./r2-media";

const renderPage = createRequestHandler(() => import("virtual:react-router/server-build"), import.meta.env.MODE);

const configByEnv = new WeakMap<Env, AppConfig>();   // only plain config is cached
function getConfig(env: Env) {
  let config = configByEnv.get(env);
  if (!config) { config = loadConfig(env as unknown as Record<string, unknown>, "cloudflare"); configByEnv.set(env, config); }
  return config;
}

// Built per request on purpose: do not cache Services or the Better Auth instance on Workers.
function buildServices(env: Env): Services {
  return createServices({
    config: getConfig(env),
    db: drizzle(env.DB, { schema }),
    media: new R2MediaStore(env.MEDIA),
    fetchClientMetadata: fetchClientMetadataViaFetch,
  });
}

export default {
  async fetch(request, env) {
    return handleRequest(request, buildServices(env), (req, svc) => renderPage(req, createRouterContext(svc)));
  },
} satisfies ExportedHandler<Env>;
```

`Env` is generated by `wrangler types` into `hosting/cloudflare/worker-configuration.d.ts` (part of `npm run typegen`).

export interface Services {
  config: AppConfig; db: Database; auth: Auth; media: MediaStore; now: () => Date;

export function createServices(deps: HostDeps): Services {
  const now = deps.now ?? (() => new Date());

    publications: createPublications({ repo: createPublicationsRepository(deps.db), now, newId }),
    // …
  };
}

## 3. Core services

```ts
// server/core/publications.ts — no framework, driver, or SDK imports
import { z } from "zod";

export const publicationCreateShape = {
  externalId: z.string().min(1).max(128).describe("Your unique ID for this publication. Resending it is safe."),
  type: z.enum(["story", "report"]).describe("story or report. A daily briefing is a report tagged 'briefing'."),
  title: z.string().trim().min(1).max(200),
  summary: z.string().trim().min(1).max(1000).describe("Plain text."),
  bodyMarkdown: z.string().max(100_000).optional().describe("Required for reports."),
  category: z.string().trim().min(1).max(80),
  tags: z.array(z.string().trim().min(1).max(60)).max(20).optional(),
  sources: z.array(z.object({ url: z.url({ protocol: /^https?$/ }), label: z.string().max(200).optional() })).max(20).optional(),
  attachmentIds: z.array(z.string()).max(20).optional(),
  sourcePublishedAt: z.iso.datetime().optional(),
};
export const publicationCreateSchema = z.object(publicationCreateShape)
  .refine((p) => p.type !== "report" || !!p.bodyMarkdown?.trim(), { path: ["bodyMarkdown"], message: "Reports need a body." });
```

- One schema is used by editor forms, MCP, and HTTP. MCP gets the raw shape; core runs the full refined schema.
- Factories take injected `now` and `newId`: `createPublications({ repo, now, newId })`.
- Results that can fail return discriminated unions (`{ ok: true, value }` or `{ ok: false, status, message, errors? }`), not exceptions.
- Actors are explicit: `{ kind: "member", userId, role }` or `{ kind: "agent", agentId }`. Core enforces permissions against the actor, so a protocol layer cannot bypass them.

```tsx
// app/routes/editor.publication.tsx (shape)
export async function action({ request, params, context }: Route.ActionArgs) {
  const services = context.get(servicesContext);
  const editor = await requireRoleWrite(request, services, "editor");   // first line of every write
  const form = await request.formData();
  const outcome = await services.publications.editorSave(
    { kind: "member", userId: editor.userId, role: editor.role },
    params.id, readPublicationForm(form), Number(form.get("expectedRevision")),
  );
  if (!outcome.ok) return data({ errors: outcome.errors, message: outcome.message, input: readPublicationForm(form) }, { status: statusFor(outcome) });
  return { saved: true, revision: outcome.value.revision };
}
```

- Return the submitted input with any error, so a failed save keeps the user's unsaved text and they can retry.
- The root loader returns `viewer` and the theme; components read them with `useRouteLoaderData("root")`.
- Route types come from `react-router typegen` (`import type { Route } from "./+types/<route>"`).

## 5. Errors

| Where | Pattern |
| --- | --- |
| Loaders/actions | `throw new Response(message, { status })` for 401/403/404; `return data({ errors }, { status: 422 })` for validation |
| UI | Root `ErrorBoundary` with `isRouteErrorResponse(error)`: shows the message for 401/403, a "Not found" page for 404, a generic message otherwise |
| JSON routes and HTTP API | `Response.json({ status, message }, { status })` with plain, safe messages and `Cache-Control: no-store` |
| MCP | Business errors are tool results with `isError: true`; auth errors are HTTP 401 |
| Config | `loadConfig` throws one readable error |

Public errors never reveal that a draft or unpublished item exists: return 404.

## 6. Logging and health

- Minimal logging with `console.log`/`console.error`. Workers observability collects them; stream with `npx wrangler tail 540news-site --format json`.
- Never log secrets, tokens, API keys, or request bodies.
- `/health` returns `{ ok, host, checks: { database, media } }`. It runs a trivial query (for example, `select 1` or a count on a small table) and the media `ping()`, and returns 503 when a check fails.

## 7. Input bounds and safety

- Bound every input: zod `.max()` on all schemas; a JSON body cap in the HTTP API checked on both `content-length` and actual length.
- **Markdown is untrusted.** Render with raw HTML disabled; allow only `http`, `https`, and `mailto` link protocols; rewrite `attachment:ID` images to `/attachments/ID` only when the ID is a valid attachment linked to that publication version; drop all other images. Sanitize the final HTML with an allowlist. Use the same renderer for the editor preview and the public page. Test it against script, `javascript:` link, data-URI, and HTML-injection cases (A11).
- Validate `next=` return paths as same-site relative paths.
- Never fetch source URLs.
- Same-origin check on cookie-authenticated writes ([MCP_AND_AUTH.md](MCP_AND_AUTH.md) section 3).

## 8. Theme

The theme follows the device preference (`prefers-color-scheme`) by default. An explicit choice is saved to the member's preferences when signed in, or to `localStorage` (wrapped in try/catch) for anonymous visitors. Set the theme attribute during SSR from the member's preference to avoid a flash. Define colors as CSS custom properties with light and dark sets, check contrast in both, and honor `prefers-reduced-motion`.

## 9. Tests

```ts
// tests/helpers/services.ts (essentials)
import Database from "better-sqlite3";
import { drizzle } from "drizzle-orm/better-sqlite3";
import { migrate } from "drizzle-orm/better-sqlite3/migrator";

export const BASE_URL = "http://localhost:5173";
export const OWNER_EMAIL = "owner@example.test";       // test data

export function createTestServices(options: { env?: Record<string, string>; now?: () => Date } = {}) {
  const db = drizzle(new Database(":memory:"), { schema });
  migrate(db, { migrationsFolder: "db/migrations" });   // real migrations in every test
  const config = loadConfig({
    PUBLIC_BASE_URL: BASE_URL, OWNER_EMAIL,
    BETTER_AUTH_SECRET: "test-secret-test-secret-test-secret-123",
    GOOGLE_CLIENT_ID: "test", GOOGLE_CLIENT_SECRET: "test", ...options.env,
  }, "node");
  return createServices({ config, db, media: new MemoryMediaStore(), fetchClientMetadata: fetchClientMetadataViaFetch, now: options.now });
}

export const request = (services: Services, path: string, init?: RequestInit) =>
  handleRequest(new Request(`${BASE_URL}${path}`, init), services, async () => new Response("<html>page</html>"));

/** Signed session cookie for a member with a role (stands in for Google sign-in). */
export async function sessionCookieFor(services: Services, email: string, role: Role = "reader") {
  const { serializeSignedCookie } = await import("better-call");
  const ctx = await services.auth.$context;
  const id = crypto.randomUUID(), now = new Date();
  await services.db.insert(schema.user).values({ id, email, name: "Test member", emailVerified: true, createdAt: now, updatedAt: now });
  await insertMembership(services, id, role);
  const session = await ctx.internalAdapter.createSession(id);
  return (await serializeSignedCookie("better-auth.session_token", session.token, ctx.secret)).split(";")[0]!;
}
```

Patterns:

- **Route tests** call `loader`/`action` directly with `{ request, params, context: createRouterContext(services) }`. A small `run()` helper catches thrown `Response`s and unwraps `data()` results (`type === "DataWithResponseInit"`, status in `init.status`).
- **MCP tests** send JSON-RPC through `request(services, "/mcp", …)` with an agent API key, or with a token from `connectAgent()`, which runs the full OAuth flow in-process (register → authorize → owner consent with agent mapping → token, with PKCE). Parse either JSON or SSE `data:` lines.
- **Concurrency tests** fire identical creates with `Promise.all`, over MCP and HTTP, and assert one publication (A5).
- **Browser tests** run Playwright against the Node build: a `setup` project seeds test data through the app, then phone, tablet, and desktop projects run with `workers: 1`. Use `@axe-core/playwright` for accessibility, and test both themes (A12).
- Name tests with acceptance IDs (A1–A17).
- Report which checks ran locally against fakes, which ran live, and which did not run.

## 11. How a feature uses each layer

1. **Schema:** add tables to `server/db/app-schema.ts` → `npm run db:generate` → review the SQL.
2. **Core:** types, zod validation, an `XRepository` interface, and `createX()` with injected `now`/`newId`. Permission checks against the actor live here.
3. **Adapter:** `createXRepository(db)` with Drizzle; multi-statement writes go through `atomic()`.
4. **Wire:** add it to `Services` and `createServices`.
5. **UI:** a page route with a loader and action; writes start with `requireRoleWrite`.
6. **Agents:** if agents use it, `registerTool` in `server/mcp/server.ts` and a handler in `server/api-v1.ts`, both calling the same core function and shaping output through `server/integration.ts`.
7. **Tests:** a core unit test, a route test with `createTestServices`, and MCP/HTTP tests if exposed.
