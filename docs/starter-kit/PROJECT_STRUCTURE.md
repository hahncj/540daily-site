# Project structure

Proposed tree for the new app. It mirrors the source app's layout (confirmed) with business names replaced by a neutral example domain: **items** (a generic record with a title and notes) and an **AI "suggest" feature**.

```
<app-name>/
  AGENTS.md                     Agent guidance (commands, architecture rules, workflow)
  CLAUDE.md                     One line: "@AGENTS.md" (keeps guidance in one file)
  README.md
  package.json                  Exact version pins; engines; allowScripts
  package-lock.json
  tsconfig.json
  vite.config.ts                BUILD_TARGET=cloudflare (default) | node
  react-router.config.ts        { ssr: true }
  drizzle.config.ts             dialect sqlite, schema server/db/schema.ts, out db/migrations
  eslint.config.js              typescript-eslint + core-isolation rule

  vitest.live.config.ts         tests/live/**/*.live.ts (paid; run on purpose)

  app/                          UI (React Router framework mode)
```

## Folder rules

- **`server/core/`** must not import `cloudflare:*`, `@cloudflare/*`, `wrangler`, `react`, `react-dom`, `react-router`, `@react-router/*`, `better-sqlite3`, `drizzle-orm`, `better-auth`, `@better-auth/*`, `@anthropic-ai/*`, `@modelcontextprotocol/*`, `node:*`, or anything under `adapters/` or `hosting/`. ESLint fails the build (see the rule in [IMPLEMENTATION_PATTERNS.md](IMPLEMENTATION_PATTERNS.md)). zod is allowed.
- **`hosting/*`** is the only code that reads environment variables or bindings.
- **`server/ai/`** is the only code that imports `@anthropic-ai/sdk`.
- **`server/mcp/`** and **`server/api-v1.ts`** are thin. They parse input, call core, and format output.
- **`app/`** reaches server code only from loaders, actions, and `*.server.ts` files.

## Naming conventions (confirmed from source)

- Files: kebab-case (`items-repo.ts`, `tool-auth.ts`).
- Route modules: dot-separated path segments (`api.ai.suggest.ts`, `item-edit.tsx`), registered explicitly in `app/routes.ts`.
- Server-only UI helpers end in `.server.ts`.
- Factories: `createX()` returning an object of async functions (`createItems`, `createItemsRepository`, `createAnthropicAi`). No classes, except small adapters such as `R2MediaStore`.
- Interfaces: `XRepository` for data ports; the AI port is one interface with one method per AI task.
- DB columns: snake_case in SQL, camelCase in Drizzle. Timestamps are `integer(..., { mode: "timestamp_ms" })`.
- Tests: `*.test.ts` (Vitest), `*.spec.ts` (Playwright), `*.live.ts` (paid).

## Where new features go

| You are adding | Put it in |
| --- | --- |
| A business rule or validation | `server/core/<feature>.ts` |
| A new table | `server/db/app-schema.ts`, then `npm run db:generate` |
| Data access | `server/adapters/<feature>-repo.ts` implementing an interface from core |
| A new Claude task | New method on the AI port in `server/core/ai.ts`, implemented in `server/ai/anthropic.ts`, faked in `tests/helpers/fake-ai.ts` |
| A page | `app/routes/<name>.tsx` + entry in `app/routes.ts` |
| A browser-called JSON endpoint | `app/routes/api.<area>.<name>.ts` (resource route with `action`) |
| An MCP tool | `server/mcp/server.ts` `registerTool(...)` calling a core function |
| The same operation for HTTP tools | `server/api-v1.ts` calling the same core function |
| A new service on `Services` | `server/app.ts` (`Services` interface + `createServices`) |
| A new env var | `server/config.ts` schema + `AppConfig`, `.dev.vars.example`, `wrangler.jsonc` vars or a secret |
